# Alpine Zoom — Анализ видео с воздуха для горного поиска и спасения с помощью ИИ

Набор инструментов для анализа видеозаписей с дронов и вертолётов для помощи в поиске
пропавших альпинистов в горной местности. Использует гибридный конвейер:
классическое компьютерное зрение для фильтрации кадров по качеству,
группировки сцен и обнаружения цветовых аномалий, затем
LLM с поддержкой зрения для визуального анализа.

> **История создания:** Этот набор инструментов был создан в августе 2026 года во время 
> добровольной поисково-спасательной операции вблизи пика Курумды в Кыргызстане, 
> где пропали три альпиниста из Беларуси и Литвы.

## Установка и настройка

1. **Установите Python 3.10 или новее**
   
   - Скачайте с [python.org](https://www.python.org/downloads/)
   - На Windows отметьте «Add Python to PATH» при установке
   - Проверка: `python --version`

2. **Установите Ollama**
   
   Ollama запускает большие языковые модели в облаке или локально, включая модели
   с поддержкой зрения, используемые этим проектом для анализа SAR-изображений.
   Это лёгкая среда выполнения, которая загружает и обслуживает LLM через
   локальный REST API по адресу `http://localhost:11434`.

   - **macOS:** Скачайте установщик с https://ollama.com
   - **Linux:** `curl -fsSL https://ollama.com/install.sh | sh`
   - **Windows:** Скачайте с https://ollama.com (нативная сборка)
   - **Docker:** `docker pull ollama/ollama && docker run -d -v ollama:/root/.ollama -p 11434:11434 ollama/ollama`

   После установки Ollama работает как фоновый сервис. Проверка:
   ```bash
   ollama --version
   ```

   Основные команды:
   - **Загрузить модель:** `ollama pull <модель>` — загружает в локальное хранилище
   - **Запустить модель:** `ollama run <модель>` — запускает интерактивный чат (автозагрузка при отсутствии)
   - **Список моделей:** `ollama list` — показывает установленные модели
   - **API-сервер:** `ollama serve` — запускает API-сервер (обычно автозапуск при установке)
   - **Модели с поддержкой зрения:** принимают изображения через эндпоинт `/api/chat`
     с base64-кодированными изображениями в содержимом сообщения

   Этот проект в основном использует облачные модели Ollama (например, `gemma4:31b-cloud`,
   `qwen3.5:397b-cloud`). Это размещённые модели, доступные через Ollama API у
   облачного провайдера — локальный GPU не требуется. Убедитесь, что быстрая и
   глубокая модели доступны; если нет, загрузите их:
   ```bash
   ollama pull gemma4:31b-cloud
   ollama pull qwen3.5:397b-cloud
   ```

   Для двухэтапного режима также загрузите модель рассуждений:
   ```bash
   ollama pull glm-5.1:cloud
   ```

   Эти модели можно переопределить параметрами командной строки инструментов этого набора.
   
3. **Клонируйте этот репозиторий**
   Допустим, вы планируете поместить инструмент, например, в папку `~/Projects/`:
   
   ```
   cd ~/Projects
   git clone https://github.com/andreisminsk/alpine-zoom-sar.git
   cd alpine-zoom-sar
   ```

4. **Создайте виртуальное окружение** (macOS/Linux)
   
   Виртуальное окружение (venv) — это изолированное рабочее пространство Python.
   Оно отделяет зависимости этого проекта (OpenCV, numpy, Pillow и т.д.) от
   системного Python и других проектов, предотвращая конфликты версий. На macOS
   и Linux это **иногда обязательно** — системный Python часто защищён ОС
   (например, Homebrew или Xcode toolchain), и `pip install` завершится ошибкой
   «externally-managed-environment». Venv обходит это ограничение.
   
   Откройте терминал в папке `alpine-zoom-sar` (например, `~/Projects/alpine-zoom-sar`), затем:
   
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   ```
   
   - `python3 -m venv venv` создаёт окружение в подпапке `venv/` (выполните
     **один раз**, при первом использовании).
   - `source venv/bin/activate` активирует его. В приглашении оболочки появится
     `(venv)` — это значит, что окружение активно, и `pip`/`python` теперь
     указывают на него.
   
   **При последующих сеансах** просто повторно активируйте перед запуском любого инструмента `az-*`:
   
   ```bash
   source venv/bin/activate
   ```
   
   **Деактивация** после завершения (или для возврата к системному Python):
   
   ```bash
   deactivate
   ```
   
   **Windows** — та же идея, другие команды. В `alpine-zoom-sar` выполните в
   PowerShell или CMD:
   
   ```powershell
   py -3 -m venv venv
   .\venv\Scripts\Activate.ps1
   ```
   
   (В CMD используйте `venv\Scripts\activate.bat` вместо `.ps1`.) Если PowerShell
   блокирует скрипт, выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`.
   
   **Устранение неполадок:**
   - `python3: command not found` → установите Python 3.10+ (шаг 1) и повторите.
   - `ModuleNotFoundError: No module named 'venv'` (Debian/Ubuntu) →
     `sudo apt install python3-venv`.
   - После активации `az-*` всё ещё не найдены → повторите `pip install -e .`
     (шаг 5) **пока venv активен**, чтобы команды установились в него.

5. **Зависимости Python**

```bash
pip install -e .
```

> **После обновлений:** Если вы выполняете `git pull` для получения изменений кода, большинство из них вступают в силу немедленно (режим редактирования). Но если изменился `pyproject.toml` (новые зависимости, новые команды, изменение версии), повторите `pip install -e .`, чтобы подхватить их. Это безопасно выполнять в любое время.

Требуется для анализа видео (`ffprobe`).

- **Windows:** Скачайте с https://ffmpeg.org/download.html, добавьте в PATH
- **macOS:** `brew install ffmpeg`
- **Linux:** `sudo apt install ffmpeg`

Проверка:
```bash
ffprobe -version
```

7. **Google Drive (опционально)**

Для загрузки видеоматериалов из общих папок Google Drive:
```bash

```

## Использование

### Анализ всех видео
```bash
az-batch [параметры]
```
Обрабатывает все видео в `source_video/`, создаёт результат в `analysis_results/`.
Пропускает видео с существующим `report.json`. Автоматически определяет папки вертолётов (HELI в имени).

Все параметры `az-video` доступны как аргументы `az-batch` и передаются напрямую.
Значения по умолчанию настроены для пакетной обработки (напр. `--scene-sim 0.65` вместо 0.82).
По умолчанию включены `--llm-run`, `--build-preview` и `--color-anomalies`.

| Параметр | По умолчанию | Описание |
|-----------|--------|-------------|
| `--stride` | `dynamic` | Интервал выборки кадров (передаётся в az-video) |
| `--quality` | `0.5` | Порог качества (передаётся в az-video) |
| `--scene-sim` | `0.65` | Порог сходства сцен (по умолчанию в az-video — 0.82) |
| `--dedup-thresh` | `0.90` | Порог дедупликации сцен (передаётся в az-video) |
| `--llm-scenes-cap` | `50` | Максимум сцен для быстрой LLM |
| `--llm-deep-max-scenes` | `20` | Максимум сцен для глубокой LLM |
| `--llm-fast-model` | `gemma4:31b-cloud` | Быстрая LLM-модель |
| `--llm-deep-model` | `qwen3.5:397b-cloud` | Глубокая LLM-модель |
| `--llm-pipeline` | `fast` | Режим LLM-конвейера: `fast`, `chancepeek`, `max` |
| `--llm-parallel` | `0` | Параллельные LLM-воркеры (0 = последовательно, 4 для облака) |
| `--llm-no-two-stage` | выкл | Отключить двухэтапную LLM для глубокого прохода |
| `--llm-reasoning-model` | `glm-5.1:cloud` | Модель рассуждений для двухэтапного режима |
| `--context-file` | Нет | Путь к JSON-файлу контекста миссии |
| `--context-preset` | Нет | Именованный пресет: `sar`, `sar-heli` |
| `--no-llm-run` | выкл | Пропустить LLM-анализ (только сцены/изображения) |
| `--no-build-preview` | выкл | Пропустить сборку превью-видео |
| `--no-color-anomalies` | выкл | Пропустить обнаружение цветовых аномалий |

### Анализ одного видео
```bash
az-video <видео> [параметры]
```
| Параметр | По умолчанию | Описание |
|-----------|--------|-------------|
| `video` | (обязательный) | Путь к видеофайлу с дрона/вертолёта |
| `-o, --output` | `<имя_видео>.AZ/` | Выходной каталог (по умолчанию — имя видеофайла + `.AZ`, например `video1.mp4.AZ/`). Суффикс `.AZ` предотвращает конфликт с исходным видеофайлом при запуске из каталога видео. |
| `--stride` | `dynamic` | Интервал выборки кадров. Целое число (каждый N-й кадр) или `dynamic` (по умолчанию, адаптивный к движению). Dynamic считывает каждый кадр и адаптируется: stride 1 (каждый кадр) при быстром движении/зуме, до 20 при медленных панорамированиях. Всплеск зума (>60px сдвига) принудительно немедленно фиксирует кадр. Использует фазовую корреляцию для измерения межкадрового сдвига. |
| `--quality` | `0.5` | Порог качества (0-1). Кадры с оценкой ниже этого значения отфильтровываются. Оценка объединяет дисперсию Лапласиана (резкость), фазовую корреляцию (движение камеры), экспозицию и контраст. Ниже = больше кадров проходят (менее строго); выше = меньше, но более резких кадров. В режиме вертолёта автоматически снижается до 0.4. Сцены с качеством ниже 0.4 сохраняются как изображения, но не отправляются в LLM (защита бюджета). |
| `--scene-sim` | `0.82` | Порог сходства сцен (0-1). Кадры сравниваются с использованием нормализованной взаимной корреляции 16×16 полутоновых сигнатур. Если сходство кадра с ключевым кадром текущей сцены превышает этот порог, кадр группируется в эту сцену. Ниже (напр. 0.65) = больше различных сцен (кадры должны сильнее отличаться для создания новой сцены). Выше (напр. 0.90) = меньше сцен (только очень разные кадры начинают новые сцены). В режиме вертолёта по умолчанию 0.55 (агрессивная группировка из-за быстрого движения камеры). Локально по таймлайну: совпадение только в пределах 300 кадров для предотвращения слияния похожего рельефа в разное время. |
| `--llm-fast-model` | `gemma4:31b-cloud` | Быстрая LLM-модель для первичного прохода |
| `--llm-deep-model` | `qwen3.5:397b-cloud` | Глубокая LLM-модель для подтверждения |
| `--llm-deep-max-scenes` | `20` | Максимум сцен для отправки в глубокую LLM (положительные или положительные+chancepeek отрицательные) |
| `--llm-scenes-cap` | `50` | Максимум сцен для отправки в быструю LLM (распределение по таймлайну). Целое число или `all`. |
| `--helicopter` | выкл | Режим вертолёта (ослабленные пороги, автозагрузка пресета `sar-heli`) |
| `--llm-pipeline` | `fast` | Режим LLM-конвейера: `fast` (быстрый — оценивается вариант кадра v3, остановка при обнаружении, глубокий анализ положительных), `chancepeek` (длиннее — глубокий анализ также запускается на отрицательных результатах быстрого, последняя надежда на ложноотрицательные), `max` (самый длинный, самая глубокая оценка всех вариантов кадров, без остановки при обнаружении, глубокий анализ всех вариантов для положительных). |
| `--from` | Нет | Начать обработку с этого времени (секунды). По умолчанию: начало |
| `--to` | Нет | Закончить обработку на этом времени (секунды). По умолчанию: конец |
| `--llm-run` | выкл | Запустить LLM-анализ (по умолчанию выключен — генерируются только сцены/изображения). Используйте `az-llm` для отдельного запуска LLM на существующих результатах. |
| `--build-preview` | выкл | Сборка превью-видео (hq/lq/цветовые аномалии). По умолчанию выключено для ускорения пакетной обработки. |
| `--dedup-thresh` | `0.90` | Порог дедупликации сцен (ПРОХОД 2.5). Объединяет почти-дубликаты сцен через временные интервалы с использованием сходства 32×32 полутоновых + цветовых гистограмм. Установите `0` для отключения. Отлавливает возврат камеры к той же точке обзора с разницей в минуты. |
| `--color-anomalies` | выкл | Включить обнаружение цветовых аномалий относительно сцены. Находит небольшие цветные области, чей цвет статистически редок для сцены (оранжевый, синий, красный, зелёный и т.д.). Использует LAB-цветовость + редкость гистограммы. Фильтрует шум через минимальную площадь (50px), минимальную редкость (2.5) и маску игнорирования текстовых маркеров. Сохраняет аннотированные изображения в `scenes/anomalies/` и собирает `preview_color_anomalies.mp4` (оригинал + аномалия, по 1с каждый). |
| `--recording-time` | Нет | Переопределить время записи (формат ISO, напр. '2026-08-15 12:08:14'). Используйте, когда часы камеры неправильные. |
| `--context-file` | Нет | Путь к JSON-файлу контекста миссии. Переопределяет `--context-preset` и `--helicopter`. См. примеры в `contexts/`. |
| `--context-preset` | `sar` | Именованный пресет: `sar`, `sar-heli`. Переопределяет `--helicopter`. По умолчанию (ничего не указано) загружается `sar`. |
| `--llm-no-two-stage` | выкл | Отключить двухэтапную LLM для **глубокого** прохода (включено по умолчанию). **Быстрый** проход всегда одноэтапный. Двухэтапный (только глубокий): модель с описывает сцену (без оценки), модель рассуждений делает вывод из описания + контекста. Использует `--llm-deep-model` как модель с, `--llm-reasoning-model` как модель рассуждений. |
| `--llm-reasoning-model` | `glm-5.1:cloud` | Модель рассуждений для двухэтапного режима (только текст, без изображения). |
| `--llm-parallel` | `0` | Количество параллельных LLM-воркеров (0 = последовательно). Облачные модели могут обрабатывать 4+ одновременных запросов (~5x ускорение). Локальные модели должны оставаться на 0 (ограничение VRAM). См. `LLM.PARALLELISM.md` для деталей бенчмарков. |
| `--run-standard` | выкл | Пресет: полный анализ с LLM. Устанавливает `--color-anomalies --build-preview --llm-run --llm-parallel 4 --llm-pipeline chancepeek`. Отдельные флаги переопределяют пресет. |
| `--run-light` | выкл | Пресет: сцены + изображения + цветовые аномалии + превью, без LLM. Устанавливает `--color-anomalies --build-preview`. Отдельные флаги переопределяют пресет. |

### Обнаружение цветовых аномалий на существующих результатах
```bash
az-colors <выходной_каталог> [--debug] [--skip-update-report]
```
| Параметр | По умолчанию | Описание |
|-----------|---------|-------------|
| `output_dir` | (обязательный) | Выходной каталог видео с report.json и scenes/ (как az-previews) |
| `--debug` | выкл | Сохранить отладочные тепловые карты (маска аномалий, цветовость, редкость) |
| `--skip-update-report` | выкл | Не записывать `dynamics.color_findings` обратно в report.json |

Сканирует `scenes/hq/` и `scenes/lq/` на файлы `_orig.jpg`, записывает
аннотированные `_color_anomalies.jpg` изображения в `scenes/anomalies/` и
(по умолчанию) обновляет `report.json` с `dynamics.color_findings`, чтобы
`az-previews` мог собрать `preview_color_anomalies.mp4`. Использует общий
помощник `build_dynamics()`, поэтому структура отчёта точно совпадает с
`az-video --color-anomalies`.

### Обнаружение геометрических аномалий на существующих результатах
```bash
az-geometry <выходной_каталог> [--debug]
```
| Параметр | По умолчанию | Описание |
|-----------|---------|-------------|
| `output_dir` | (обязательный) | Выходной каталог видео с report.json и scenes/ (как az-previews) |
| `--debug` | выкл | Сохранить отладочные тепловые карты (контуры, контуры) |

Обнаруживает искусственные геометрические формы (линии, прямоугольники, окружности,
правильные многоугольники), статистически маловероятные в природном рельефе.
Использует анализ контуров, преобразования Хафа и проверку направления градиента
для окружностей. Сканирует `scenes/hq/` и `scenes/lq/` на файлы `_orig.jpg`,
записывает аннотированные `_geometry_anomalies.jpg` изображения в `scenes/anomalies/`.

### Сборка превью-видео
```bash
az-previews <выходной_каталог>
```
| Параметр | Описание |

Структура вывода:
```
scene_32_f00810/

  scene_32_f00810_grid_v2.jpg      # мягкий CLAHE
```

### Генерация контекста миссии из текстового описания
```bash
az-context -i <текст или файл> -o <output.json> [параметры]
```
Превращает свободное текстовое описание поисковой ситуации в структурированный JSON
контекста миссии (та же схема, что и `contexts/sar.json`), используя LLM рассуждений.
Результат можно передать обратно в конвейер через `--context-file`.

| Параметр | По умолчанию | Описание |
|-----------|--------|-------------|
| `-i, --input` | (обязательный) | Описание ситуации: буквальный текст или путь к текстовому файлу (автоопределение) |
| `-o, --output` | (обязательный) | Путь к выходному JSON (напр. `contexts/my-mission.json`) |
| `--llm-reasoning-model` | `glm-5.1:cloud` | LLM-модель рассуждений (только текст) |
| `--llm-timeout` | `180` | Таймаут LLM в секундах |
| `--name` | основание имени выходного файла | Имя пресета, записываемое в поле `name` JSON |

Сгенерированный JSON содержит шесть полей `MissionContext`: `context`,
`natural_list`, `priority_signals`, `target_objects`, `platform_notes`,
`color_shift_notes`.

```bash
az-context -i "Альпийский гребень выше 4500м, два альпиниста пропали после срыва,
ищем оранжевый пуховик и снаряжение на снегу и скалах" -o contexts/ridge.json
az-context -i situation.txt -o contexts/ridge.json --llm-reasoning-model qwen3.5:397b-cloud
```

### Контекст миссии

Промпт LLM состоит из двух частей: встроенный **фундаментальный промпт**
(универсальное обнаружение аномалий, не редактируется) плюс опциональный
**контекст миссии** (правила для конкретной миссии, добавляемые к нему).
Контекст миссии может поступать из двух мест:

- **Встроенные пресеты** — определены в `src/alpine_zoom/context.py`
  (`PRESETS = {"sar", "sar-heli"}`). Ссылаются по имени через
  `--context-preset sar` / `--context-preset sar-heli`. Файл не нужен.
- **JSON-файлы в `contexts/`** — редактируемые примеры/шаблоны. Они **не**
  загружаются автоматически; нужно указать явно через `--context-file
  contexts/sar.json`. Файлы `contexts/sar.json` и `contexts/sar-heli.json`
  дублируют встроенные пресеты и существуют как отправные точки для копирования
  и настройки (напр., результат `az-context`).

Приоритет разрешения (от высшего к низшему):

```
--context-file  >  --context-preset  >  контекст из report.json  >  флаг --helicopter  >  по умолчанию (sar)
```

- `--context-file contexts/sea.json` → загружает ваш сгенерированный/кастомный файл
- `--context-preset sar` → использует встроенный пресет `sar`
- `--helicopter` → автоматически загружает встроенный пресет `sar-heli`
- ничего из вышеперечисленного → используется пресет `sar` по умолчанию (контекст горного SAR)

### Сравнение моделей
| Модель | Скорость | Зрение | Статус |
|-------|-------|--------|--------|
| gemma4:31b-cloud | 6.5с | ✅ | Быстрый проход — все сцены (всегда одноэтапный) |
| qwen3.5:397b-cloud | 54.6с | ✅ | Глубокий проход — только положительные / модель с в двухэтапном |
| glm-5.1:cloud | ~3с | ❌ | Модель рассуждений для двухэтапного глубокого прохода (только текст) |
| minimax-m3:cloud | 14.7с | ✅ | Доступна как резервная |
